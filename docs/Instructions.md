## ⚖️ BRUTALLY HONEST AUDIT MANDATE

As of May 2026, the Council has moved to a **Zero-Tolerance Audit Framework**. All future technical reviews, architecture assessments, and progress reports MUST adhere to the following rules:

1. **Brutal Honesty:** Never sugarcoat problems. If an architecture is brittle, call it brittle. If a security measure is "theater," label it as such.
2. **Zero Generic Praise:** Vague statements like "UI is modern" or "Code is clean" are strictly forbidden. Every strength must be backed by a specific engineering metric or pattern.
3. **Enterprise Benchmarking:** Always benchmark against Fortune 500 / Hyperscale standards, not just "startup-grade" functionality.
4. **Penalize Missing Evidence:** If a feature is claimed as "Done" but lacks formal testing, observability, or documentation, it must be downgraded.
5. **Investor-Ready Skepticism:** Always evaluate the system as if a $100M acquisition or a mission-critical enterprise contract depends on its stability.

**The Council's verdict is final and engineering-led. Truth precedes politeness.**
